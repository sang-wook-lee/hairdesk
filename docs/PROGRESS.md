## 완료한 것

### 백엔드 API (33개)

| 도메인 | 엔드포인트 | 핵심 규칙 |
|---|---|---|
| 시술 메뉴 | `POST/GET/PUT /api/menus`, `POST /{id}/deactivate·activate` | 삭제 대신 **판매 중지**(과거 매출 보존) |
| 고객 | `POST`, `GET`(검색), `GET /{id}`, `PUT /api/customers` | (이름, 번호) 조합 중복 불가, 번호는 숫자만 저장, 문자 수신 동의 기본값 false — ADR 0002 |
| 예약 | `POST`, `GET`(기간), `GET /{id}`, `PATCH /{id}/time`, `POST /{id}/cancel·complete·no-show` | **같은 직원의 겹치는 시간은 DB 제약(EXCLUDE)으로 차단**(직원이 다르면 같은 시간 가능), 담당자 `staffId` **필수** — ADR 0003·0010·0011 |
| 매출 | `POST`, `GET`(기간), `GET /summary`, `GET /{id}`, `PUT /api/sales` | 결제 = 예약 자동 완료, 예약당 1건(UNIQUE), 메뉴 이름·정가 **스냅샷** — ADR 0004 |
| 직원 | `POST/GET/PUT /api/staff`, `POST /{id}/deactivate·activate` | 직원 번호(id)로 구분(이름·직책 중복 가능), 직책 "원장"은 여러 명 가능, 모든 직원이 같은 규칙(**owner 개념 없음**), 삭제 대신 근무 종료 — ADR 0010·0011 |
| 통계 | `GET /api/stats/sales/daily·monthly·by-menu`, `/customers`, `/reservations` | 실시간 집계, 서울 날짜 기준, 신규/재방문·노쇼율 정의 — ADR 0005 |

공통: ProblemDetail 에러 응답(RFC 9457), DTO(record)로만 응답, Flyway 마이그레이션 5개(V1~V5), Swagger UI(`/swagger-ui.html`), 개발용 샘플 데이터 자동 입력(`DevDataSeeder`).

## 구조와 개발 방식

```
hairdesk/
├── backend/   Spring Boot 4.1 (Java 21) — customer · menu · reservation · sales · stats · common
├── app/       Flutter — lib/core (API 클라이언트·시간·포맷) + lib/features/<기능>/
├── docs/
│   ├── PROGRESS.md   (이 문서)
│   ├── adr/          설계 결정 기록
│   └── blog/         블로그 초안
└── CLAUDE.md  개발 규칙
```

- **백엔드**: 도메인별 패키지(`controller` / `service` / `repository` / `domain` / `dto`). 컨트롤러는 변환만, 규칙은 서비스·엔티티에. 스키마 변경은 Flyway로만.
- **앱**: 기능별 폴더, 모델 / 저장소 / 화면 3계층, 상태는 `setState`, 의존성은 생성자 주입 — ADR 0006. 서울 시각 변환은 `core/kst.dart` 한 곳.
- **원칙**: 개발자가 AI 없이도 이해·유지보수할 수 있어야 한다. 기능 하나 = **설계 설명 → 구현 → 테스트 → 커밋**, 중요한 결정은 ADR로.

## 테스트와 품질

| 영역 | 개수 | 방식 |
|---|---|---|
| 백엔드 | 135 | `@SpringBootTest` + Testcontainers(PostgreSQL), API·DB 제약·시드·CORS 규칙 검증 |
| 앱 | 256 | 단위(모델·계산·시간), 위젯(가짜 저장소 주입), 저장소(MockClient로 요청 모양 검증) |

**테스트·눈으로 확인하며 잡은 문제들** (같은 실수를 반복하지 않으려고 기록)
- 예약 시간 변경: 엔티티를 먼저 바꾸면 조회 직전 자동 flush로 DB 제약이 먼저 터짐 → 변경 **전에** 겹침 확인.
- Dart 3 레코드 `(a, b).wait`는 에러를 `ParallelWaitError`로 감싸 서버 메시지가 사라짐 → `Future.wait` 목록 방식.
- Dart `List.sort`는 같은 값의 순서를 보장하지 않음 → 비교 기준에 원래 번호 추가.
- 가로 막대가 **안 보임**: 내용 없는 `ColoredBox`는 `Row` 기본 정렬에서 높이 0 → `stretch` + 높이 검증 테스트. (너비만 재는 테스트는 통과했음)
- 빠른 실행 칸의 글자가 **폰 폭에서 잘림**: 폭 비율로 높이를 정하면 좁은 화면에서 너무 낮아짐 → 고정 높이.
- 교훈: **시각 위젯은 폰 폭(375px)으로 직접 보고 확인**한다.

| 환불·정정 이력 | 매출은 정정만 가능, 이력·환불 없음 | 백엔드 로드맵 |

./gradlew test

# 앱 (app/에서)
C:\dev\flutter\bin\flutter run -d chrome
C:\dev\flutter\bin\flutter test

## 문서 관리

- **갱신 시점**: 기능 하나 또는 층 하나를 커밋할 때 같이 갱신합니다. (진행 현황 표, 타임라인, 로드맵 체크박스, 테스트 개수, 알려진 이슈)
- **로드맵 체크**: 끝낸 항목은 `[x]`로 바꾸고, 완료한 것/타임라인 쪽으로 옮깁니다.
- **숫자의 출처**: 커밋 수는 `git log --oneline | wc -l`, 테스트 수는 `./gradlew test`·`flutter test` 결과, 진행률은 체감 추정치입니다.
- 설계 결정은 이 문서가 아니라 `docs/adr/`에 쓰고, 여기에는 표로 링크만 둡니다.
- **진행 현황 웹 페이지**: `docs/progress-page/`에 원본 템플릿과 빌드 스크립트(`python docs/progress-page/build.py`)가 있습니다. 이 문서의 숫자·로드맵을 고쳤다면 템플릿의 같은 내용도 고친 뒤 다시 만들어 게시합니다. (게시된 페이지는 스냅샷입니다)
