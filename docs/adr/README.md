# ADR (Architecture Decision Record)

"왜 이렇게 만들었는가"를 남기는 기록. 코드는 *무엇*을 보여주지만 *왜*는 보여주지 않는다.
6개월 뒤의 나, 그리고 면접관이 읽을 문서다.

## 규칙

- 파일명: `NNNN-짧은-영문-제목.md` (번호는 1씩 증가)
- 한 번 확정된 ADR은 고치지 않는다. 결정이 바뀌면 새 ADR을 쓰고, 이전 ADR의 상태를 `대체됨(→ NNNN)`으로 바꾼다.
- 상태: `제안` → `승인` → (필요 시) `대체됨`

## 템플릿

```markdown
# NNNN. 제목

- 상태: 제안 | 승인 | 대체됨
- 날짜: YYYY-MM-DD

## 배경
어떤 문제/상황 때문에 결정이 필요했는가.

## 결정
무엇을 선택했는가.

## 검토한 대안
각 대안과 채택하지 않은 이유.

## 결과
이 결정으로 얻는 것, 감수하는 것.
```
