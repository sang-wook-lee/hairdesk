# 0009. 개발 중 폰으로 보기: 사설 IP 출처만 CORS 허용, 서버 주소는 빌드 설정으로

- 상태: 승인
- 날짜: 2026-11-18

## 배경

앱을 폰으로 보고 싶다. 서버(백엔드, DB)는 개발 PC에서만 돌고, 앱은 서버를 `localhost:8080`으로 부르도록 고정돼 있었다.
폰에게 `localhost`는 폰 자신이라서 서버를 찾지 못한다. 서버 쪽도 CORS가 `localhost` 출처만 허용해서,
폰 브라우저가 `http://192.168.x.x:5173`에서 보내는 요청을 거절한다.

로그인(인증)이 아직 없어서 서버를 인터넷에 공개할 수는 없다. 우선 "같은 와이파이의 폰으로 개발 PC의 앱을 열어 보는" 범위만 지원한다.

## 결정

1. **앱의 서버 주소는 빌드할 때 정한다.** `--dart-define=API_BASE_URL=주소`. 안 주면 기존대로 `http://localhost:8080`이라서 평소 개발은 달라지지 않는다.
2. **서버 CORS는 두 종류의 출처만 허용한다.** ① `localhost`, `127.0.0.1` (기존) ② **사설 네트워크의 IPv4 주소** (10.x.x.x, 172.16~31.x.x, 192.168.x.x, 포트는 아무거나).
3. **사설 IP 판단은 문자열 패턴이 아니라 숫자를 직접 읽어서 한다.** 출처가 `http://숫자.숫자.숫자.숫자[:포트]` 형태이고 각 숫자가 0~255(앞에 0 없음)이며 사설 대역일 때만 허용한다. https와 경로가 붙은 값, 도메인 이름은 허용하지 않는다.
4. 그래서 `WebMvcConfigurer`의 CORS 매핑 대신 **출처를 직접 판단할 수 있는 `CorsFilter`** 를 쓴다.
5. 폰용 실행은 `scripts/phone-preview.ps1` 한 줄로 한다 (와이파이 주소 찾기 → 그 주소로 빌드 → 폰이 열 수 있게 서빙).

## 검토한 대안

- **패턴 `http://192.168.*:*`**: 가장 쉽지만 `*`가 아무 글자와 일치해서 `192.168.evil.com` 같은 **도메인 이름도 통과**한다. 숫자로 시작하는 도메인도 만들 수 있기 때문에, 인터넷의 사이트가 내 개발 서버를 호출하는 길이 열린다. 테스트에 이 경우를 넣어 막혔음을 확인한다.
- **모든 출처 허용(`*`)**: 설정은 가장 쉽지만 개발 서버가 아무 웹사이트에서나 호출될 수 있다.
- **PC의 IP를 환경변수로 하나만 허용**: 가장 엄격하지만 와이파이 주소가 바뀔 때마다(DHCP) 서버 설정을 바꿔야 한다. 사설 대역 전체를 허용하는 쪽이 개발 편의와 안전의 균형이 낫다고 판단했다.
- **터널 서비스(ngrok 등)로 인터넷에 임시 공개**: 어디서나 열리지만 인증 없는 서버가 공개되고, 외부 계정 가입이 필요하다. 인증을 만들기 전에는 하지 않는다.
- **클라우드 배포**: 상시 접속은 되지만 인증·HTTPS·비용 결정이 먼저다. 로드맵 P3.

## 결과

- 얻는 것: 같은 와이파이의 폰으로 실제 서버 데이터를 보면서 화면을 확인할 수 있다. 서버 코드는 CORS 설정 한 곳만 바뀌었고, 규칙은 단위 테스트(경계값, 우회 시도 포함)로 고정했다.
- 감수하는 것
  - **와이파이 주소가 바뀌면 앱을 다시 빌드해야 한다**(주소가 빌드에 박히므로). 스크립트가 매번 새로 찾아 빌드한다.
  - **개발 DB 포트(5432)가 PC의 모든 네트워크에 열려 있고 비밀번호가 `salon`/`salon`이다.** 같은 네트워크의 다른 기기가 DB에 직접 붙을 수 있으므로, **믿을 수 있는 네트워크(집)에서만** 쓴다. 필요하면 방화벽에서 8080, 5173 포트만 허용한다.
  - 사설 IP를 허용하는 규칙은 개발용이다. 운영 배포 때는 실제 웹 주소 하나로 좁혀야 한다.
- 추후 과제: 상시 공개용 데모 모드(서버 없이 샘플 데이터로 동작) 검토, 인증 도입 후 실서버 배포.
