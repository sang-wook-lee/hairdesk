## 올리기 전 체크리스트

- [ ] 본문에 **[직접 채우기]**, **[직접 확인]** 표시와 맨 위의 쓰는 사람용 메모(주석)가 남아 있지 않은가
- [ ] 제목·요약을 본인 문체로 다듬었는가 (초안은 개발 일지 톤)
- [ ] AI 도구 사용을 어디까지 공개할지(프롤로그 "AI와 일하는 방식", 챕터 1의 4절) 확인했는가
- [ ] 개인정보가 없는가 — 화면의 이름·전화번호는 **샘플 데이터(가짜)** 입니다. 실제 고객 정보를 캡처에 넣지 마세요
- [ ] 비밀값(비밀번호, 키)이 코드 조각에 없는가 — 현재 글에는 없음
- [ ] 먼저 **비공개**로 올려 서식을 확인했는가 (아래 "시험 발행 결과" 참고)

## 네이버 블로그에 올리는 방법

**피클(폰 앱)이 GitHub에서 글을 받아 네이버 블로그에 올립니다.** (네이버의 글쓰기 API는 종료됐지만, 피클이 블로그 글쓰기 화면을 직접 조작하는 방식이라 가능합니다.) 흐름은 이렇습니다.

1. PC에서 Claude Code로 `docs/blog/`에 글을 쓰고 직접 검토한 뒤 `git push` 합니다.
2. 폰의 피클에게 "저장소 `sang-wook-lee/hairdesk`의 `docs/blog/○○.md`를 네이버 블로그에 올려 줘"라고 요청합니다. 처음에는 **비공개**로 올려서 확인하세요.
3. 확인한 뒤 공개로 바꿉니다. 이미지는 `images/` 폴더의 파일을 쓰는데, 아직 시험하지 않았습니다. (첫 이미지 글에서 확인)

### 시험 발행 결과 (2026-11-22, 챕터 1, 비공개)

| 마크다운 | 네이버에서 |
|---|---|
| 제목·목록·구분선·굵게 | 잘 변환됨 |
| 인용구(`>`) | 변환되지만 **가운데 정렬**이 기본 |
| 표 | 들어가지만 안쪽 격자선이 없고 바깥 테두리만 흐림. 에디터에서 표마다 테두리 색을 지정할 수 있음 |
| 코드 블록 | 붙여넣으면 일반 문단이 됨. 피클이 에디터의 "소스코드 추가"로 직접 넣어서 SQL 하이라이팅까지 정상 |
| 인라인 코드(백틱) | 전용 서식이 없어 **백틱이 빠지고 일반 글자**로 나옴 |

그래서 글을 쓸 때 이렇게 합니다.
- 중요한 용어는 백틱 대신 **굵게**로 강조하면 서식이 살아남습니다.
- 코드는 짧게 쓰고, 코드 블록은 피클이 소스코드 기능으로 넣어 주는 것을 전제로 합니다.
- 맨 위 주석(`<!-- -->`)은 발행 전에 지웁니다.
- 피클이 자동으로 붙이는 태그(예: `#첫글`)는 발행 전에 확인합니다.

> 피클 없이 직접 올릴 때는 글을 붙여 넣고 서식을 에디터에서 다시 지정하면 됩니다. 마크다운을 그대로 쓸 수 있는 곳(velog, GitHub 블로그)에는 이 `.md` 파일을 거의 그대로 올릴 수 있습니다.
