# 블로그 글감 메모

개발하면서 "글로 쓸 만하다" 싶은 일을 그때그때 적어 두는 곳이다. 날짜, 무슨 일이 있었는지, 왜 글감인지를 몇 줄씩만 적는다.
하루 개발을 마칠 때 이 메모와 ADR, 커밋 기록으로 챕터 초안을 쓴다. (이 파일은 블로그에 올리는 글이 아니라 재료다.)

---

## 2026-11-19

- **ErrorView를 두고 "이게 뭐냐"부터 물었다.** 홈·일정·메뉴·통계에 똑같은 오류 화면 코드가 4개 복붙돼 있어서 하나로 합쳤다. 정리하기 전에 "ErrorView가 오류를 적어 두는 오답노트냐"고 물었고, 사용자에게 보이는 오류 화면이라는 걸 알고 나서야 작업을 시켰다. 이해하고 나서 시킨다는 원칙의 작은 사례.

## 2026-11-20 ~ 21 직원(담당자) 기능

- **고객 관리 화면을 하려다가 순서가 바뀌었다.** 고객 이력에 담당자를 보여주려면 직원 개념이 먼저 있어야 해서, 고객 화면 전에 직원부터 만들기로 했다. 처음 계획에 없던 일이 앞으로 끼어든 경우.
- **AI가 설계를 안 보여주고 먼저 구현하려다 지적받았다.** "작업 전에 어떤 컬럼을 추가할지 설계부터 보여줬어야지." 이후 방식이 바뀌었다: 설계 설명 → 선택지 → 작은 단위로 멈추고 확인. 글감: AI와 일하는 속도를 사람이 조절한 순간.
- **현장 지식으로 설계를 고친 세 가지.**
  - 오너는 한 명이어도 원장은 두 명 이상일 수 있다 → 직책 컬럼 추가.
  - 한 고객이 같은 시간에 두 명 이상의 디자이너에게 예약할 수 있다(가족 손님: 어머니와 자녀) → 겹침 규칙을 직원별로.
  - 이름도 직책도 같은 직원이 있을 수 있다 → 이름이 아니라 직원 번호로 구분.
- **내가 만든 "오너" 설계를 사용자가 통째로 뒤집었다. (ADR 0011)** AI는 "주인 지정"과 "원장 기본 담당" 같은 기능을 넣으려 했다. 사용자가 "주인은 총책임자일 뿐이고 매번 바꾸는 게 아니다. 사업체 주인은 시술을 안 할 수도 있다"고 짚었고, `owner` 개념을 아예 삭제했다. 담당자는 기본값 없이 항상 직접 고르게 했다. ADR 0010의 결정 일부를 0011이 번복한 기록도 남겼다. **이 사례는 챕터 1 4절(누가 무엇을 정하나) 표의 가장 좋은 증거.**
- **권한은 일부러 미뤘다.** 근무 종료(퇴사 처리)를 아무나 못 하게 하려면 권한이 필요한데, 로그인이 없다. 로그인을 붙일 때 "계정(관리자/일반)"과 "직원"을 분리하기로 하고 알려진 이슈에 적어 뒀다.
- **챕터 1에서 건 복선이 회수됐다.** 첫날 "디자이너가 늘면 `designer_id WITH =` 한 줄을 추가하면 된다"고 적었는데, 실제로 `staff_id WITH =`로 바뀌었다(마이그레이션 V7). 첫날 구상한 모양 그대로.
- **테스트가 처음부터 통과하면 오히려 의심했다.** 코드를 일부러 망가뜨려서 테스트가 잡는지 확인했더니, 검사를 지워도 통과하는 테스트가 있었다. (영속성 컨텍스트 때문에 flush 코드가 없어도 통과, 상태 코드만 보는 테스트는 다른 경로가 같은 코드를 내도 통과.) 오류 메시지까지 확인하도록 고쳤다.
- **JSON에서 `"noShowRate":0.0`을 문자열로 찾던 테스트가 0.068에서 깨졌다.** 숫자는 문자열이 아니라 숫자로 읽어서 비교한다.
- **화면 테스트는 통과했는데 폰 폭에서만 글자가 잘렸다.** "시술 메뉴 | 직원" 전환 버튼이 글자 폭만큼만 좁게 그려져 "시술 메뉴"가 두 줄로 잘렸다. 위젯 테스트의 글꼴이 브라우저의 한글 글꼴과 달라서 테스트로는 재현이 안 됐다. 375px 브라우저로 직접 보고서 발견. (챕터 10 "테스트가 통과했는데 화면이 틀렸던 사례들"에 들어갈 사례.)
- **직원이 1명이면 담당자를 숨겼다.** 혼자 일하는 사용자에게 모든 예약 줄에 같은 이름이 반복되면 소음이라서, 직원이 2명 이상일 때만 "담당 이지수 (#2)"를 보여준다. 근무를 마친 직원도 센다(지난 예약에 남아 있어서).
- **AI는 세션이 바뀌면 이전 대화를 기억하지 못한다.** Docker Desktop이 꺼져 있을 때 이전 세션에서는 알아서 켜 줬는데 새 세션에서는 "켜 주세요"라고 물었다. 그래서 "개발 환경은 AI가 직접 켠다"를 메모리에 적었다. 글감: AI와 오래 일할 때 기록이 기억을 대신한다.

## 2026-11-22 블로그 올리기

- **네이버 블로그 글을 피클(폰 AI 에이전트 앱)이 GitHub에서 받아 올린다.** 처음엔 "네이버는 자동 게시가 불가능하다"고 적었는데(API 종료), 실제로는 피클이 블로그 글쓰기 화면을 조작해서 올렸다. 시험 발행으로 확인하고 문서를 고쳤다. 변환 결과: 표는 되지만 격자선이 흐림, 인용구는 가운데 정렬, 백틱은 사라짐, 코드 블록은 소스코드 기능으로 따로 넣어짐.
- **공개 저장소에 올리기 전에 비밀값을 검사했다.** 비밀번호·키 패턴을 커밋 기록 전체에서 찾았고, 개발용 DB 계정(`salon/salon`)과 집 와이파이 사설 IP 주소 예시, 커밋 작성자 이메일이 공개되는 것을 확인하고 판단했다.
- **글 말투가 "AI티가 난다"는 지적.** "저/제가 ~습니다"를 "나/내가 ~다"의 일기체로 바꿨다. 같은 내용도 말투 하나로 내 글인지 아닌지가 갈린다.
- **글의 "1인 전용" 서술이 사실과 달라서 고쳤다.** 처음엔 1인 미용사만 대상으로 했고 지금은 여러 명으로 확장 중이라는 점, 비슷한 앱이 이미 있고 문제는 기능이 아니라 쓰기 편한 정도라는 점을 반영.
- **쓰고 나서 시간이 지나면 숫자가 낡는다.** 프롤로그의 커밋·API·테스트 수와 SQL 코드가 직원 기능 이후 틀려져서 발행 직전에 고쳤다. 숫자는 글을 쓰는 시점에 PROGRESS.md에서 가져온다.

## 2026-11-24 고객 요약 API

- **"방문"을 무엇으로 셀까.** 예약 완료로 세면 예약 없이 온 손님이 빠진다. 매출 기록으로 세기로 했다(워크인 포함, 결제 안 한 예약은 방문이 아님). 이력은 방문만 보여 주고 앞으로의 예약은 "예정"으로 따로.
- **첫 방문일은 고객 등록일이 아니다.** 먼저 등록해 두고 한참 뒤에 처음 올 수 있어서, 첫 매출 기록의 날짜로 계산한다. 값을 저장하지 않고 조회할 때 계산하는 이유: 저장하면 매출을 정정할 때마다 어긋난다.
- **같은 모양의 한 줄짜리 파일(StatusCount)을 재사용할까, 따로 만들까.** 통계 쪽에 이미 있었는데, 고객 코드가 통계 코드에 기대면 한쪽 수정이 다른 쪽을 깨뜨리고 나중에 순환 의존이 생길 수 있다. 위험은 작지만 비용도 한 줄이라 따로 만들었다. 의존성이 "있어도 되는 것"과 "만들지 않는 편이 싸다"의 차이.
- **SUM은 행이 없으면 0이 아니라 null이다.** 매출이 없는 고객의 총 결제액이 null로 나오는 걸 서비스에서 0으로 바꾸고, 평균은 방문 0이면 null로 둔다(0으로 나누지 않으려고).
- **쿼리를 7가지로 망가뜨려 테스트를 확인했는데, 첫 시도는 아무것도 망가뜨리지 못했다.** 변경 스크립트에 줄바꿈 오류가 있어서 결과가 전부 무효였다. 변경이 실제로 적용됐는지 먼저 확인하도록 고쳐서 다시 돌렸다. "테스트가 통과했다"만큼 "내가 의도한 걸 실제로 했는가"도 확인해야 한다.
- **전체 테스트를 돌렸더니 내 변경과 무관한 테스트가 실패했다.** 샘플 데이터 테스트가 오늘이 화~목일 때만 신규 고객 0명으로 실패. 내 변경을 치워도 똑같이 실패해서 "원래 있던 문제"로 구분했고, 날짜를 바꿔 요일 7개로 돌려 원인(시더가 일요일을 건너뛰어 난수 순서가 요일마다 달라짐)을 증명한 뒤 기간을 14일에서 21일로 고쳤다.
- **"푸시를 안 하고 커밋만 쌓은 이유가 뭐냐"는 질문.** 공개 저장소라 허락 없이 올리지 않기로 했던 건데, 쌓이는 동안 물어보지 않은 게 문제였다. 이후 작은 단위마다 푸시 의사를 묻기로 했다.

## 챕터 후보 (README의 계획 표와 맞춰서 정리할 것)

- **#직원-1 "오너를 지웠다"** 가족 예약, 직책, 동명이인, 오너 삭제(ADR 0010, 0011) → 챕터 1의 복선 회수와 4절 표의 증거
- **#직원-2 "통과한 테스트를 믿지 마라"** 일부러 망가뜨리기, 상태 코드만 보는 테스트, 요일에 따라 실패한 테스트
- **#고객 "고객 한 사람을 어떻게 요약하나"** 방문의 정의, 계산값은 저장하지 않는다, null 처리
- **#AI-1 "AI와 일하는 속도"** 설계 먼저 보여 달라는 지적, 오너 설계를 뒤집은 일, 세션이 바뀌면 기억이 사라지는 문제
- **#블로그 "피클로 블로그 올리기"** 시험 발행 결과, 말투, 비밀값 검사
